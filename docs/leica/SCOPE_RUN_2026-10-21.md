**Acceptance checklist** from the installed-driver run, all PASS:

- installed by folder
- connected by name, every `get_*` answer fits the contract
- every command answers in the controller's shape
- a limits file governs the session
- the limits gate refuses before anything moves
- a move is read back where it was asked
- the controller accepts an acquisition

The stage was taken to the CI baseline (X 63,500 um, Y 41,500 um, z-wide 0, z-galvo 0) before the
first moving step and was back there when the run ended. Every job was selected once (`AF Job`,
`HiRes`, `Overview`) and each switch was confirmed in about 0.1 to 0.3 s.

### Saving and clearing

- **One capture of `Overview`** (512 x 512, two channels, 8 bit) was saved as one OME-Zarr store.
  It is valid OME-Zarr 0.5 and valid OME 2016-06, it has no projection because it is a single
  plane, and the log sits beside the data. The capture took 4.7 s.
- **Ten captures, each saved and then cleared**, in 52 s. LAS X's cache (`D:\Temp2`) grew by
  1.1 MB over the ten, and the hidden copies did not grow (-0.1 MB). So every Clear press freed
  what the capture had left behind.

### What was skipped, and why

None of the skips is a problem. They are the validators' deliberate opt-outs:

- **Autofocus** needs `--allow-autofocus`, which `run_ci` does not pass.
- **The objective turret** needs `--allow-objective`, which `run_ci` never passes.
- **Detector gain:** the HyD S 2 exposes no writable gain range, so the validator does not touch it.
- **The baseline step** runs with moves, state and acquisition switched off on purpose; the later steps do those.

## 2. What to look at

### 2.1 The first attempt failed on an old controller, not on the driver

The first run, a few minutes earlier, failed five steps. Every failure had the same cause: the
env still had `zmart-controller` 0.3.0. That controller expects two values from `get_info` where
this driver now answers three (`description`, `setup`, `chooses_its_own_folder`), and it calls
`acquire` without `acquisition_type` and `output_folder`. Every move, setting and job switch in
that run was read back correctly and restored, but nothing was captured. After installing 0.4.0rc1,
the version this branch pins, the same command passed. When the contract and acquire steps all fail
together, check the installed controller first.
